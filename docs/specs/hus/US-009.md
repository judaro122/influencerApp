# US-009: Subscribe to Kafka Events (System Administrator)

## As a system administrator, I want to subscribe to Kafka events so I can trigger downstream workflows.

## Given / When / Then

- **Given** Kafka is running and events are being produced.
- **When** an administrator subscribes to the `video-received` or `video-published` topics.
- **Then** the administrator receives structured JSON event payloads that can be consumed by downstream systems.

## References

- **Kafka Schema**: `docs/specs/arq/kafka-events.md` — Event schemas (§4), topics (§3), DLQ topics (§6), Outbox pattern (§7).
- **Data Model**: `docs/specs/arq/data-model.md` — Kafka event payload schemas: `video-received` (§4.2), `video-published` (§4.3).
- **Architecture**: `docs/specs/arq/architecture.md` — Topic naming (kebab-case, plural), schema versioning (§9.2), consumer idempotency via `processed_events` table (§8.3).
- **Constitution**: §6.1 — Schema Registry: all event payloads MUST be versioned. §6.2 — Consumers MUST be idempotent. §6.3 — DLQ after 3 retries. §6.4 — No binary data in payloads.

## Acceptance Criteria

1. The `video-received` topic carries events when a video is stored and validated (schema in kafka-events.md §4.2).
2. The `video-published` topic carries events when a video is successfully published to YouTube (schema in kafka-events.md §4.3).
3. All events contain `schemaVersion` (`"1.0.0"`), `tenantId`, `correlationId`, `videoId`, `channelId`, `timestamp`, and `payload`.
4. Event payloads contain no binary data; only storage paths/URIs for video references.
5. The `{tenantId}-video-received` and `{tenantId}-video-published` topic variants are recommended for tenant-scoped consumption.
6. Failed events (after 3 retries) are routed to `video-received-dlq` or `video-published-dlq`.
7. The `processed_events` table prevents duplicate event processing (consumer idempotency).
8. The `outbox_events` table ensures no event loss when Kafka is temporarily unavailable.
9. Downstream consumers MUST be idempotent and handle duplicate deliveries gracefully.

## Out of Scope

- Custom consumer implementations (consumer logic is outside platform scope).
- WebSocket or SSE for real-time client notifications (v1.0, out of scope per constitution §11.4).
