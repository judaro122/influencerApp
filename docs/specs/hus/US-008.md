# US-008: Check Video Processing Status

## As an authenticated user, I want to check the status of my upload so I know if it succeeded or failed.

## Given / When / Then

- **Given** an authenticated user with a known `videoId`.
- **When** the user sends a GET request to `/api/videos/{videoId}`.
- **Then** the current status and metadata of the video are returned (HTTP 200).

## References

- **API Contract**: `docs/specs/arq/openapi.yaml` — `/api/videos/{videoId}` (GET) endpoint and `VideoStatusResponse` schema.
- **Data Model**: `docs/specs/arq/data-model.md` — `Video` aggregate (§2.1), `VideoStatus` enum (§2.4), `VideoStatusResponse` DTO (§5.2).
- **Security**: `docs/specs/security-spec.md` — Tenant isolation (§3); cross-tenant access forbidden (constitution §4.2).
- **Constitution**: §4.2 — Users MAY only access their own channels and videos.

## Acceptance Criteria

1. GET `/api/videos/{videoId}` returns HTTP 200 with a `VideoStatusResponse` containing the current `status`, `title`, `description`, `youtubeVideoId` (nullable), `youtubeUrl` (nullable), and `errorReason` (nullable).
2. The `videoId` must belong to the requesting tenant (`tenantId` from JWT); otherwise, `404` is returned (not `403`, to avoid leaking existence).
3. Returns `401` (RFC 7807) when no valid JWT is provided.
4. Returns `404` (RFC 7807) when the video does not exist or belongs to a different tenant.
5. All status values are returned correctly: `RECEIVED`, `PROCESSING`, `UPLOADING`, `PUBLISHED`, `FAILED`.
6. On `FAILED` status, `errorReason` contains a human-readable description of the failure.

## Out of Scope

- Real-time push notifications for status changes (v1.0; WebSocket/SSE out of scope per constitution §11.4).
