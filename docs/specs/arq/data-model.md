# InfluencerAPP - Data Model Specification

## 1. Overview

This document defines the canonical data model for the InfluencerAPP platform. It synthesizes requirements from the [Product Requirements Document](../PRD.md), the [Project Constitution](../constitution.md), and the [Architecture Specification](architecture.md).

All domain models are immutable value-centered aggregates. JPA entities in the infrastructure layer map 1:1 to domain models per constitution §3.3. Every entity and event payload includes tenant isolation per constitution §2 and architecture §6.

---

## 2. Domain Model

### 2.1 Aggregates

#### Video (Aggregate Root)

| Field | Type | Description |
|-------|------|-------------|
| `videoId` | `VideoId` (VO) | Unique identifier |
| `tenantId` | `TenantId` (VO) | Owner tenant; used for all isolation queries |
| `channelId` | `ChannelId` (VO) | Target YouTube channel |
| `fileMetadata` | `FileMetadata` (VO) | filename, size, mimeType, checksum |
| `storagePath` | `StoragePath` (VO) | Path in MinIO/object storage |
| `metadata` | `VideoMetadata` (VO) | title, description (AI-generated or placeholder) |
| `status` | `VideoStatus` (enum) | See §2.4 |
| `youtubeVideoId` | `YouTubeVideoId` (VO) | Published YouTube video ID (nullable until publish) |
| `createdAt` | `Instant` | Creation timestamp |
| `updatedAt` | `Instant` | Last status transition timestamp |

**Constraints:**
- Status transitions are strict: `RECEIVED → PROCESSING → UPLOADING → PUBLISHED` or `FAILED` at any stage.
- `youtubeVideoId` is null until `PUBLISHED` status is reached.
- `StoragePath` must be tenant-prefixed: `tenants/{tenantId}/videos/{videoId}/{filename}`.

#### Channel (Aggregate Root)

| Field | Type | Description |
|-------|------|-------------|
| `channelId` | `ChannelId` (VO) | Unique identifier |
| `tenantId` | `TenantId` (VO) | Owner tenant |
| `youtubeChannelId` | `String` | YouTube channel ID from OAuth2 |
| `youtubeChannelTitle` | `String` | Human-readable channel name |
| `encryptedTokens` | `EncryptedTokens` (VO) | access_token, refresh_token, token_expiry — AES/GCM/NoPadding encrypted |
| `scope` | `String` | Fixed to `https://www.googleapis.com/auth/youtube.upload` |
| `createdAt` | `Instant` | |
| `updatedAt` | `Instant` | |

**Constraints:**
- `encryptedTokens` must NEVER be stored or logged in plaintext per constitution §4.3.
- Token encryption uses AES/GCM/NoPadding with key from `${ENCRYPTION_KEY}` (falls back to `${JWT_SECRET}`) per constitution §4.3.
- `YouTubeUploadAdapter` refreshes `access_token` transparently before upload per architecture §11.2.

### 2.2 Value Objects

| VO | Fields | Description |
|----|--------|-------------|
| `TenantId` | `value` (String) | Unique tenant identifier; extracted from JWT `sub` claim |
| `VideoId` | `value` (String) | Unique video identifier |
| `ChannelId` | `value` (String) | Unique channel identifier |
| `FileMetadata` | `filename`, `size` (bytes), `mimeType`, `checksum` | Immutable; validated on upload per constitution §4.6 |
| `StoragePath` | `value` (String) | Full object storage key; always tenant-prefixed |
| `YouTubeVideoId` | `value` (String) | YouTube-assigned video identifier |
| `YouTubeUrl` | `value` (String) | Resolvable YouTube watch URL |
| `VideoMetadata` | `title`, `description` | Generated by Gemini or fallback placeholder |
| `EncryptedTokens` | `access_token`, `refresh_token`, `token_expiry` | All fields encrypted at rest |

**Immutability:** All value objects are immutable (constitution §3.4). Use `@Value` (Lombok) or `final` fields with `@RequiredArgsConstructor`.

---

### 2.3 Value Objects — FileMetadata Detail

| Field | Type | Constraint |
|-------|------|------------|
| `filename` | `String` | Sanitized (no path traversal); max length enforced |
| `size` | `long` | Must not exceed `spring.servlet.multipart.max-file-size` (default 100MB) |
| `mimeType` | `String` | Must match `video/*` per constitution §4.6 |
| `checksum` | `String` | SHA-256 or equivalent for integrity verification |

---

### 2.4 Enums

#### VideoStatus

| Value | Description |
|-------|-------------|
| `RECEIVED` | Video file accepted and stored; awaiting processing |
| `PROCESSING` | AI metadata generation in progress |
| `UPLOADING` | Upload to YouTube in progress |
| `PUBLISHED` | Successfully published to YouTube |
| `FAILED` | Processing or upload failed; error details in `errorReason` |

## 7. Multi-Tenancy Data Isolation

All data access is tenant-scoped per constitution §2 and architecture §6:

1. **Database queries**: Every repository query includes `WHERE tenant_id = :tenantId`. Cross-tenant data leakage is a P0 violation.
2. **Object storage paths**: `tenants/{tenantId}/videos/{videoId}/{filename}`. No storage operation bypasses tenant prefix.
3. **Kafka payloads**: `tenantId` is a top-level field in every event. Consumers filter by tenant context.
4. **Authorization**: Every use case validates that `TenantId` from the JWT matches the resource's tenant. `TenantIsolationViolationException` is thrown on mismatch (constitution §3.4, architecture §12.2).

---

## 8. Encryption at Rest

Per constitution §4.3 and architecture §11.3:

- **Algorithm**: AES/GCM/NoPadding
- **Key source**: `${ENCRYPTION_KEY}` environment variable; falls back to `${JWT_SECRET}`
- **Scope**: `access_token`, `refresh_token`, `token_expiry` in `channels` table (encrypted columns in `ChannelEntity`)
- **Service**: `TokenEncryptionService` in infrastructure security adapter
- **Constraint**: Tokens are NEVER stored or logged in plaintext. Decryption occurs only in-memory during YouTube upload operations.

## 9. Naming Conventions

| Element | Convention | Example |
|---------|-----------|---------|
| Table names | `snake_case`, plural | `videos`, `channels`, `processed_events` |
| Column names | `snake_case` | `video_id`, `tenant_id`, `youtube_channel_id` |
| Enum values | `UPPER_SNAKE_CASE` | `RECEIVED`, `PROCESSING`, `PUBLISHED`, `FAILED` |
| Topic names | kebab-case, plural | `video-received`, `video-published` |
| VO class names | PascalCase, suffixed with `VO` or `Id` | `TenantId`, `VideoId`, `FileMetadata` |
| Entity classes | PascalCase, suffixed with `Entity` | `VideoEntity`, `ChannelEntity` |
| Enum classes | PascalCase | `VideoStatus` |
| Event classes | PascalCase, suffixed with `Event` | `VideoReceivedEvent`, `VideoPublishedEvent` |

## 10. Data Retention (Open Question)

The constitution and PRD do not specify a retention policy for video files in object storage. This is tracked as an open question in the PRD (§12). Until resolved, no data lifecycle automation is applied to stored video files or event payloads.
